- **Сеть**: TCP-сокеты (IPv4).

## 2. Описание легенды и функционала сервиса [↑](#содержание)
**Secure Note** — это консольное приложение для защищённых заметок. Оно позволяет пользователям регистрироваться, авторизовываться и сохранять свои личные заметки в зашифрованном виде на сервере. Основной принцип работы — каждый пользователь может получить доступ только к своей заметке, идентификация происходит по уникальному случайному идентификатору (`user_id`).

### Функционал сервиса:
**1. Регистрация**
- Пользователь вводит логин и пароль.
- Сервис генерирует уникальный 32-символьный идентификатор `user_id` (шестнадцатеричная строка).
- Логин, хеш пароля и `user_id` сохраняются в файл `data/users.txt`.
- Создается пустой файл для заметки `data/notes/{user_id}.txt`.

**2. Авторизация**
- Пользователь вводит логин и пароль.
- Сервис проверяет соответствие в `users.txt`.
- При успехе в переменную сессии `current_user_id` записывается идентификатор пользователя.
- На экран выводится приветствие с `user_id`.

**3. Запись заметки**
- Пользователь вводит текст заметки (максимум 256 символов).
- Текст сохраняется в файл `data/notes/{user_id}.txt`, перезаписывая предыдущее содержимое.
- При записи удаляются файлы токенов и истории (`*.token`, `*.last_ids`) для обновления безопасности.

**4. Чтение заметки**
- Пользователь вводит `user_id`.
- Если введенный ID совпадает с `current_user_id`, сервис читает файл `data/notes/{user_id}.txt` и выводит содержимое.
- Если ID не совпадает, выводится сообщение об ошибке доступа.
- В рамках чтения генерируется **токен операции** на основе истории последних `user_id` (для дополнительной логики проверки чекера).

**5. Скачивание заметки**
- Пользователь вводит `user_id` для скачивания.
- Сервис читает заметку пользователя и **трансформирует её содержимое**:
  1. Добавляет случайный префикс (10000 символов) и суффикс (10000 символов) из случайных ASCII-символов.
  2. Реверсирует блоки по 4 символа.
  3. Переворачивает всю строку.
- Трансформированное содержимое отправляется клиенту с маркерами `=== ПОЛНОЕ СОДЕРЖИМОЕ ЗАМЕТКИ ===` и `=== КОНЕЦ ЗАМЕТКИ ===`.
- **Важно**: Этот функционал создан для проверки целостности данных и используется чекером, который умеет обратно восстанавливать оригинальный текст из трансформированного. Для обычного пользователя этот режим позволяет скачать заметку в "защищённом" (обфусцированном) виде.

**6. Выход из аккаунта**
- Сбрасывается переменная `current_user_id`.
- Пользователь возвращается в главное меню.

## 3. Описание флагсторов [↑](#содержание)
В сервисе `Secure Note` флаг хранится в самом очевидном месте — в тексте заметки пользователя.
- **Путь к файлу**: `data/notes/{user_id}.txt`
- **Формат**: Флаг записывается в файл как обычная строка (например, `flag{...}`) при выполнении команды `write_note`.
- **Механизм проверки**:
  1. Чекер регистрирует пользователя.
  2. Записывает флаг в заметку.
  3. Сохраняет `user_id` как `flag_id`.
  4. При проверке авторизуется под этим пользователем и читает заметку. Совпадение содержимого с флагом гарантирует корректную работу сервиса.
- **Доступ**: Флаг защищен логикой сервиса (доступ только владельцу), но уязвим для эксплуатации через форматную строку.

## 4. Описание уязвимостей [↑](#содержание)
### Уязвимость: Format String (форматная строка)
> **Характеристики уязвимости:**
> - **Название**: Format String (CWE-134: Uncontrolled Format String)
> - **Вектор атаки**: Локальный (сетевое взаимодействие через TCP)
> - **Уровень опасности**: Критический (позволяет прочитать заметки других пользователей)

#### Краткая суть
В функции `read_note()` при выводе содержимого заметки используется вызов `send_printf(note)`, где `note` — это строка, введенная пользователем. В языке C это прямой путь к выполнению спецификаторов формата (`%p`,` %s`, `%n` и т.д.). Атакующий может внедрить эти спецификаторы в свою заметку, чтобы читать память стека, а затем перезаписать указатель `current_user_id`, заставив сервер считать, что он авторизован под любым другим пользователем (жертвой).

#### Шаги к эксплуатации (на основе sploit.py)
##### 1. Регистрация и авторизация
Атакующий регистрирует пользователя с логином `1` и паролем `1` (или любым другим) и успешно авторизуется в системе.
##### 2. Запись пейлоада для дампа памяти 
Атакующий записывает заметку, содержащую 85 спецификаторов `%p`, разделенных точками:
```Text
%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p.%p
```
**Почему 85 спецификаторов?** Это количество, достаточное для того, чтобы "пройти" по стеку и найти все интересующие адреса, включая указатели на строки с `user_id` других пользователей.

##### 3. Чтение заметки (дамп стека)
Атакующий читает свою заметку. Сервер выполняет `printf` с этим пейлоадом, и в ответ получает множество hex-значений (адресов), например:
```Text
0x7ffd1234abcd.0x7ffd1234abce.0x64.0x55aa11223344.0x7ffd1234abd0.0x7ffd1234abe0.0xa3f5c8e9d2b1a7c4e6f8d9b2a3c5e7f9...
```

##### 4. Извлечение user_id из дампа
Сплоит парсит ответ сервера, извлекая все hex-значения, которые выглядят как адреса (начинаются с `0x`):
```Python
hex_values = re.findall(r'0x[a-f0-9]{16}', data)
```
Затем каждый hex-адрес конвертируется в ASCII-строку (little-endian). Например, `0x6133663563386539` превращается в a3f5c8e9 и так далее. Это позволяет восстановить строки, на которые указывают адреса в стеке.

##### 5. Сборка блоков по 32 символа
Все декодированные строки объединяются, а затем разбиваются на блоки по 32 символа. Поскольку `user_id` имеет длину ровно 32 символа (шестнадцатеричная строка), каждый такой блок с высокой вероятностью является ID пользователя.
```Python
chunks_32 = [combined[i:i+32] for i in range(0, len(combined), 32)]
```
##### 6. Удаление дубликатов и выбор кандидатов
Сплоит удаляет дубликаты и берет первые 10 уникальных блоков. Это делается потому, что в дампе памяти могут встречаться повторяющиеся строки, а также сам ID атакующего. Первые 10 уникальных блоков с большой вероятностью содержат ID других пользователей системы.
```Python
first_10_chunks = unique_chunks[:10]
```

##### 7. Скачивание заметок жертв
Для каждого найденного `user_id` сплоит использует команду `3. Скачать заметку`, которая возвращает **трансформированное содержимое** заметки (с добавленным мусором, реверсированное и перевернутое):
```Python
def download_notes(s, user_ids):
    for idx, user_id in enumerate(user_ids, 1):
        s.send(b'3\n')  # Выбор команды "Скачать заметку"
        s.send((user_id + '\n').encode())  # Отправка ID жертвы
        # Получение трансформированного содержимого
```

##### 8. Восстановление оригинального текста
Сплоит применяет обратное трансформирование, чтобы восстановить оригинальный текст заметки из трансформированного:
```Python
def reverse_transform_bytewise(data: bytes) -> bytes:
    # 1. Переворот строки
    content.reverse()
    # 2. Реверс блоков по 4 символа
    # 3. Удаление префикса/суффикса (10000 символов с каждой стороны)
```

##### 9. Получение флага
Восстановленный текст заметки сохраняется в файл `flags.txt`. Если в заметке жертвы был флаг (например, `flag{...}`), он будет успешно извлечен и записан.

#### Что делает скрипт автоматически:
1. Регистрируется под пользователем `1` (пароль `1`).
2. Записывает заметку с 85 спецификаторами `%p`.

9. Восстанавливает оригинальный текст из трансформированного.
10. Сохраняет все найденные флаги в `flags.txt`.

#### Инструкция по фиксу (без доступа к файлу `secure_note_server.c`)
Для устранения уязвимости необходимо изменить и запатчить способ вывода строки в функции `read_note()` с помощью [IDA Free](https://hex-rays.com/ida-free).
- **Файл**: `secure_note_server`
- **Функция**: `read_note()`

##### Было (уязвимый код):

###### Стало (безопасный код):
```C
// ... внутри read_note()
send_printf("Ваша заметка: ");
send_printf("%s\n", note); // <-- Фикс
```
```Text
.text:0000000000002FCA                 lea     rax, [rbp+var_380]
.text:0000000000002FD1                 mov     rsi, rax
.text:0000000000002FD4                 lea     rax, aS_0       ; "%s\n"
.text:0000000000002FDB                 mov     rdi, rax
.text:0000000000002FDE                 mov     eax, 0
.text:0000000000002FE3                 call    send_printf
.text:0000000000002FE8                 jmp     short loc_2FFE
```

**Пояснение**: Использование спецификатора `%s` заставляет функцию `printf` интерпретировать переменную `note` как строку, а не как шаблон форматирования. Таким образом, любые символы `%` будут выведены как обычный текст, и атака станет невозможной.

## 5. Как деплоить сервисы [↑](#содержание)
Сервис упакован в Docker-контейнер для упрощения развертывания.

### Особенности деплоя
- Нет необходимости в дополнительных системных зависимостях (кроме [Docker](https://www.docker.com/)).
- Сервис компилируется внутри контейнера при сборке.
- Данные хранятся внутри контейнера, при пересборке они очищаются (если не используется постоянный том).

### Краткое описание развертывания
#### 1. Сборка образа:
```Bash
docker-compose build
```

#### 2. Запуск сервиса:
```Bash
docker-compose up -d
```

#### 3. Проверка работы:
Сервис будет доступен по адресу `localhost:4444`. Проверить работу можно через `netcat`:
```Bash
nc localhost 4444
```
### Специфические требования к системе
- **Docker** версии 20.10+.
- **Docker Compose** версии 2.0+.
- Доступный порт **4444** на хост-машине.
- 50 МБ свободного места для образов и данных.

## 6. Как деплоить чекеры [↑](#содержание)
Чекеры предназначены для валидации работоспособности сервиса и проверки сохранности флагов в системе A&D (Attack & Defense).

### Особенности деплоя
- Чекеры написаны на Python 3 и используют только стандартную библиотеку (`socket`, `json`, `re`).
- Не требуют установки внешних зависимостей (все модули встроены в Python).
- Взаимодействуют с сервисом по TCP (сокетам).

### Краткое описание развертывания
#### 1. Установка прав на выполнение:
```Bash
chmod +x checkers/secure_note/checker.py
```

#### 2. Локальное тестирование сервиса через `checker.py`:
Перейдите в директорию `./services/secure_note/`
```Bash
make
```
Перейдите в директорию `./checkers/secure_note/`
```Bash
DEBUG=true python3 checker.py check localhost --debug
```

#### 3. Запуск валидации через `check.py`:
Система валидации использует скрипт check.py из корня репозитория. Для запуска проверки выполните:
```Bash
export SERVICE=secure_note
./check.py up
./check.py check
```
**Примечание**: Эта команда автоматически поднимет контейнеры (если они не запущены) и выполнит полный цикл тестов: регистрация, запись, чтение, проверка токена, скачивание с трансформацией.
